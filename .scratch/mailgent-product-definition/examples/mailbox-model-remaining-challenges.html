Challenge A — Gmail Archive is not a label

You proposed: for Gmail, archive = remove INBOX and add an Archive label. Yahoo archive = move to Archive folder. Yahoo side is fine. Gmail side fights the real provider.

What Gmail actually does
Invoice #4412 — Acme Corp
user clicks Archive in Gmail
INBOX Finance Vendors/Acme

Archive only removes INBOX. Other labels stay. There is no system label called ARCHIVE. The message still exists in All Mail.

What “add Archive label” would invent
Invoice #4412 — Acme Corp
MailGent-only fiction unless you create a user label
INBOX Archive Finance

If MailGent adds a real user label Archive, it will not match mail archived in Gmail web / Apple Mail (those only dropped Inbox). Policies and search for “Archive” will miss them.

Yahoo — your mapping is fine

Challenge B — “Labels for both” needs two layers

Calling Yahoo folders “labels” is fine as a teaching metaphor if MailGent separates placement (where the mail lives) from flags (read, starred, …). Otherwise agents will try illegal second labels on Yahoo.

Layer Gmail Yahoo Cardinality
Placement Inbox, Trash, user labels like Finance… Inbox, Archive, Finance folder… Gmail: many · Yahoo: exactly one
Flags UNREAD, STARRED, IMPORTANT… \Seen, \Flagged… Both: many flags allowed with the one placement
Legal on Yahoo Placement Inbox + flag Starred + flag Unread. Still only one placement label.
Illegal on Yahoo Placement Inbox + placement Finance at once. That is a Gmail-only pattern. Agent must get a clear fail-closed error.
Human / agent intent
“Also put this in Finance, keep Inbox”
↓
Gmail
Add placement label Finance. Inbox stays. Done.
Yahoo
Cannot. Must choose: stay Inbox, or move (replace placement with Finance).
Decision needed Confirm product language:
Option B1 — recommended
UI may say “labels”; agent/API contract says placement (max 1 on Yahoo) plus separate flags.
Option B2
Call everything “labels” in API too, and encode Yahoo exclusivity only as a runtime error when a second label is added (weaker clarity for agent authors).
Mostly decided — one gap
