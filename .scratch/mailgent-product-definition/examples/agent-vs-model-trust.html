Agent vs model — where your trust ladder fits

Your intended order is: LAN model → local Cursor agent → remote agent. MailGent can enforce trust on who connects. It cannot reliably prove which model that agent is using unless MailGent itself hosts the model — and v1 has no built-in assistant.

Model = inference brain Agent = tool-using host MailGent grants attach to agents

1. Two different things

Model
LAN LLM / Ollama / vLLM box

Sees prompts and any mail text the agent chooses to paste into the prompt. Does not hold MailGent credentials. Does not call MCP tools by itself.

← prompts
Agent / host
Cursor, Claude Desktop, custom agent

Connects to MailGent, holds grants, searches mail, creates drafts, proposes mutations. Chooses which model receives mail content.

MCP →
MailGent
Policy + mailbox gate

Authenticates the agent, enforces scopes, approvals, audit. In v1 it does not talk to your model directly.

What “trust the LAN model most” really buys

  • Inference stays on your network.
  • Less chance mail text is sent to a cloud model API.
  • Good for privacy after an agent already fetched mail.

What it does not automatically buy

  • The LAN model still only sees what the agent sends it.
  • A local Cursor agent can still exfiltrate via tools, logs, or by switching models.
  • MailGent cannot cryptographically prove “this Cursor session only uses LAN inference.”

2. Your ladder, restated as MailGent can use it

If we take your intent seriously, the ladder is really about agent deployments, not bare models:

Highest

LAN-local agent stack

A custom agent (or bridge) that lives on your LAN and is configured to use only your LAN model. This is the thing MailGent can pair and label as most trusted — because it is an agent identity.

Example: home GPU box runs model + a small MailGent MCP client that only you operate.

Middle

On-machine agent host (Cursor on this Mac)

Local transport (UDS / loopback), but the host may use cloud models, mix tools, or change backends. Still stronger than remote reachability into MailGent.

Lowest

Remote agent

Cloud host over temporary relay. No private scopes. Expiring session. Separate approval for mutations.

Not a MailGent peer

Bare LAN model alone

The model endpoint is not what MailGent authenticates. Treating “model trust” as MailGent trust mixes layers. Model locality is either a property you assert about an agent, or a separate privacy preference outside MailGent grants.

3. Can MailGent enforce “uses only LAN model”?

Approach v1 realism What it means
Trust the agent identity you pair (LAN agent / Cursor / remote) Enforceable Matches topology + pairing. Private scopes only for highest class.
Ask user to mark agent as “LAN-inference only” Honor system Useful UX signal; not proof. Cursor could still call a cloud model.
Cryptographically attest model endpoint Out of v1 Needs agent cooperation / attestation MailGent cannot force on third-party hosts.
MailGent hosts / routes the model itself Out of scope Map forbids built-in assistant in v1.

4. Recommended product framing for your ladder

Keep three (or four) agent trust classes, and treat model locality as a labeled intent on that agent — not a separate MailGent principal.

B2 — Three agent classes aligned to your ladder (recommended if you keep B) lan-local → custom LAN agent stack (highest ceiling, private scopes allowed)
machine-local → Cursor / desktop hosts on this Mac
remote → cloud agents over mediated sessions
Optional field on each agent: “intended inference: LAN / mixed / cloud” (informational, not proof).
B3 — Four classes Split machine-local further into trusted vs untrusted (throwaway CLIs), plus lan-local and remote. More precise, more pairing friction.
A+ — Two classes + inference label Only local / remote for enforcement. Your LAN model preference is a tag on local agents for your own hygiene, not a separate ceiling. Simplest, weakest match to “LAN model is most trusted.”
Challenge: if Cursor on this Mac is pointed at your LAN model, do you want it treated as machine-local (honest about what MailGent can see) or elevated to lan-local (matches your feeling, but MailGent cannot verify the model stays LAN-only)?
