1 Create the YDN application

This gives you Client ID + Client Secret. It does not unlock mail scopes by itself.

  1. Open Create Application and sign in with your Yahoo account.
  2. Fill app name (e.g. MailGent), description, homepage / callback URLs.
  3. For a native macOS app, use a custom scheme and/or loopback redirect, e.g. mailgent://oauth/callback and/or http://127.0.0.1:<port>/callback.
  4. Avoid trademarked words like “Yahoo” in the description text — the create form often rejects them.
  5. Create the app → copy Client ID and Client Secret.
  6. Store locally in .env (gitignored). Production later → Keychain / secure storage, not the app binary.
Mail checkbox on create is misleading OpenID tutorials may show Mail → Read. Commercial mail scopes still require Sender Hub approval. Prefer the commercial-access path.

3 Submit the Sender Hub mail form

This is the real application for IMAP (and optional CardDAV/CalDAV).

  1. Open Yahoo Mail API Access form.
  2. Sign in if asked (Sender Hub may show your Yahoo profile name).
  3. Fill every required field. Use the paste blocks in Form answers below.
  4. API required: check IMAP only for MailGent v1. Leave CardDAV / CalDAV unchecked.
  5. Your YDN account: email of the Yahoo account that owns the YDN app.
  6. Existing Yahoo/AOL contract? Usually No. Recent 3rd-party security audit? Usually No (Yes can help expedite if you have one).
  7. Submit. Keep a copy of what you pasted.

Description of your application / service

Description 
MailGent is a macOS companion app used alongside Apple Mail (not a replacement daily mail client). Users connect their own Yahoo Mail accounts via OAuth so MailGent can sync and display mail locally for search, read, draft review, and human-approved mutations (send, move, trash, permanent delete). The product also lets the user grant scoped, revocable access to external AI agents running on their device or via short-lived mediated remote sessions. MailGent uses Yahoo IMAP/SMTP only to serve that user’s own mailbox for these features; it does not resell API access.

Data collection and processing

Data collection and processing 
MailGent accesses the user’s Yahoo mailbox via OAuth-authorized IMAP/SMTP after the user explicitly connects the account. On the user’s Mac, MailGent stores mailbox content needed for sync, local search/indexing, draft inspection, and mutation approval. OAuth tokens are stored in the macOS Keychain. MailGent does not operate a cloud service that reads mailbox bodies. External agents only receive mail content the user has explicitly granted (scopes, capabilities, and approval for mutations). We do not scan mail to build advertising profiles. Contacts and calendar (CardDAV/CalDAV) are not requested for v1.

Data use

Data use 
Yahoo mailbox data is used only to provide MailGent’s user-facing email companion features: account connection, local sync, search/read, draft review/edit, human approval of agent-proposed mutations, policy/audit surfaces, and opening messages in Apple Mail. Data is not used for advertising segments, profiling, engagement tracking, data brokerage, or model training on user mailbox content.

Data sharing

Data sharing 
MailGent does not sell or transfer Yahoo mailbox content to advertisers or data brokers. Content stays on the user’s device by default. The only third parties that may see mail content are AI agents the user deliberately pairs and grants access to, under deny-by-default scopes; send/trash/delete/move and similar mutations still require one-shot human approval. There is no unattended public endpoint that redistributes mailbox data.

Compliance with Laws

If you can honestly claim GDPR consent + CCPA readiness → choose Yes. Otherwise choose Other and paste:

Compliance · Other 
MailGent is device-first: mailbox content and tokens stay on the user’s Mac; users connect accounts via OAuth and control agent grants, revocation, and mutation approvals. We will publish a privacy policy and obtain appropriate consent for each use case before distributing broadly. Formal GDPR/CCPA counsel review is planned before public release.

Users / API calls

Users / API calls · early estimates 
Initial phase: under 100 Yahoo users (developer and early testers). Expected API usage roughly 50–500 IMAP operations per user per hour during active use (sync, IDLE/poll, search fetch), far lower when idle. Growth after public release TBD; we will stay within Yahoo rate limits.

4 Wait and follow up

  • No public status portal; no published SLA.
  • Questions / nudges: mail-api@yahooinc.com
  • Sharing a recent 3rd-party security audit “might expedite” (per form wording).
  • Meanwhile: finish other MailGent work (issue 16 distribution; Gmail is a separate Google track).

5 After approval

  1. Confirm mail-r / mail-w appear on your YDN application profile.
  2. Record the partner name / ID Yahoo assigns — IMAP clients must send IMAP ID with NAME = that value (plus VERSION, OS, OS-VERSION).
  3. Implement OAuth Authorization Code flow; then IMAP/SMTP with the OAuth token.
  4. Yahoo hosts (from Sender Hub docs): IMAP imap.mail.yahoo.com, SMTP smtp.mail.yahoo.com.
  5. If you later support AOL: same commercial form covers AOL customers, but you need a separate OAuth client credential set for the AOL namespace.

Pitfalls read once

TrapWhat to do instead
Filling Sender Hub DKIM / sender setup That path is for outbound sending reputation. MailGent needs the Mail API Access form.
Thinking each new Yahoo inbox needs this form App approval is once. Each mailbox only does OAuth consent in the app.
Product URL on GitHub, privacy on another domain Domains must match. Host privacy on the same domain or change both URLs.
Description says “Yahoo email client” Avoid “Yahoo” in YDN create text; describe a companion beside Apple Mail.
Checking CardDAV/CalDAV “just in case” v1 is mail-only. Request IMAP only; expand later if needed.
Committing .env Keep secrets local / Keychain. Repo should gitignore .env.

This is not the Gmail setup separate track

Do not put Gmail API details on the Yahoo form. Gmail uses Google Cloud + restricted-scope OAuth verification (≈100-user cap until verified). That lands under issue 16 / implementation — not this guide.
